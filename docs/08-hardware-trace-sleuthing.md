# 08 · 未知硬件走线定论：三板斧与一个教训

> 场景：ESP32-S3 板载 microSD 卡槽，官方 BSP 零定义，网上查不到这块板的
> 引脚。目标：**不拆机、不猜**，用软件+官方资料把走线钉死。

## 结论（TL;DR）

三板斧按序打：**官方原理图（坐标级解析）→ GPIO 电气特征 → 协议级逐命令
trace**。外加一条铁律：**同族板的引脚定义不能套用**。

## 本次案例（嗒嗒 MAX35 板的 SD 卡槽）

结局：官方原理图 + 串口探针实测定论
**SD_CLK=IO43 / SD_MOSI=IO44（串口脚，0R 电阻桥）/ SD_MISO=IO21 / SD_CS=IO13**，
SPI 模式。CMD0/CMD8(R7 回显)/CMD10(读出 CID) 全通 = 物理连通铁证——
**不必等到 mount 成功才下结论**。

## 三板斧

### 1. 官方原理图：下载 PDF，坐标级解析

- 厂商 wiki 的「硬件资料」栏里有原理图 PDF（别信任何二手引脚表）。
- **别用眼睛看 PDF**。用 pymupdf 渲染裁剪区 + **文本坐标配对**：
  网络标签（SD_MISO…）的坐标与芯片网络名（GP21…）精确对齐即连线——
  本次 GP21/SD_MISO x 坐标差 0.3pt，直接钉死。
- 注意 0R/NC 电阻 = 「选贴跳线」，同一网络可能延伸到别的脚
  （本次 SD_CLK/MOSI 正是经 0R 桥到串口脚 IO43/44）。

### 2. GPIO 三态审计：插卡/拔卡 diff

- 每只脚测三态（浮空/上拉/下拉），拔插外设前后各跑一次，**看哪些脚变**。
- 卡内上拉的信号线（DAT）插卡=被上拉、拔卡=悬空；CD 开关脚插卡=低。
- ⚠️ **单次 diff 不能当结论**——本次 IO17/38 的"特征"复测不复现，
  是外设上电时序的随机漂移。**必须复现验证**，否则会带着错误假设去扫
  组合空间（白扫 252 次）。

### 3. 协议级逐命令 trace：打印原始响应

- mount 失败时，**别信错误码，打印每一步的原始响应字节**。
  本次就是靠手动 CMD0→CMD8→ACMD41→CMD10 逐条打印，才看清：
  CMD8 R7 回显 0x1AA 完美、CMD10 读出 "SanDisk SC16G" 16GB——
  **卡是真卡、线是真通**，问题只在 ACMD41 busy=0（上电初始化不完成）。
- 驱动调试日志被编译期裁剪时：调 CONFIG_LOG_MAXIMUM_LEVEL（注意是
  **choice 结构**，要选 CONFIG_LOG_MAXIMUM_LEVEL_DEBUG=y，改 int 无效）。

## 铁律：同族板 ≠ 同引脚

- 本次最大弯路：拿 lcdwiki 同尺寸同主控板（ES3C35P）的 SD 定义
  （SDMMC 5/4/6/7/2/3）直接套——那块板的 LCD/触摸/音频引脚**全不同**，
  SD 定义自然也不同。官方 wiki 里另有另一块 3.5 寸板用的是
  SD_MMC 1-bit 三线方案。**厂商的板型号矩阵比你想的碎**。
- 官方 SDK 里没有 ≠ 硬件不支持（本次官方板源码零 SD 配置，但槽能用）；
  同理官方 SDK 有 ≠ 我们板一定一样。
