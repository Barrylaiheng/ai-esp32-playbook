## 二、目录约定（分层隔离，勿跨层调用）

```
main/             入口与装配
components/bsp/   【唯一允许碰硬件】板级支持
components/ui/    【不碰硬件】只依赖 UI 框架与 bsp.h 接口
```

**铁律**：UI 层不许 include 任何硬件驱动头文件；需要硬件能力时只能走 `bsp.h`。
好处：**板子没到 / 型号没定，UI 照样能开发**（还能在 PC 模拟器里跑）。

---

## 三、开工前必读的纪律

1. **删代码前先验依赖**：改动前先全仓搜索引用，确认没人用再删。
2. **烧录需显式授权**：执行前必须先报出 **串口 + 固件绝对路径**，等确认才执行。
3. **闭环三问**：动手前自问「能不能做 / 是否闭环 / 是否自嗨」，答不上来不许开工。
4. **未验证即 Unverified**：任何没在真机或模拟器上**实际跑过 / 看过**的代码，交付时必须显式标注，不许伪装成已验证。
5. **UI 改动必须截图自检**：禁止盲改。

---

## 四、交付格式（四段式）

任何功能交付按四段报告：

- **Build**：编译是否通过（贴构建结果）
- **Host**：是否跑过 PC 模拟器
- **Device**：是否上过真机、看到了什么
- **Unverified**：哪些部分还没验证（**不许隐瞒**）

## 六、中文内容必须过的检查

设备端中文 UI 的最大坑。**改文案后必须重跑字体子集脚本**，否则出方块。

1. 列出本次界面实际用到的所有字符（含数学/理化符号）
2. 子集化命令进版本库（保证可复现）
3. 字体显式选中 + fallback 链
4. 覆盖测试（**含负例**：故意给一个清单外的字）
5. 真机逐页肉眼验收

设备端一律用**开源常规字体**；**品牌 VI 的商业字体不上设备**（固件分发授权风险）。
